# CommMonit 版本管理与 Gitee 发布设计

## 目标

为 CommMonit 建立可重复的语义化版本管理流程，并将项目作为私有仓库发布到 Gitee。首个正式版本为 `v1.0.0`，Gitee 页面显示名称为“串口旁路监控软件”，稳定仓库路径为 `yycz/commmonit`。

## 版本规则

- 使用语义化版本 `主版本.次版本.修订版本`，首版为 `1.0.0`。
- Git 发布标签统一添加 `v` 前缀，例如 `v1.0.0`。
- `app/version.py` 是唯一版本源，至少导出字符串版本号和 Windows 文件版本元组。
- 功能不兼容时提升主版本，新增兼容功能时提升次版本，兼容修复时提升修订版本。
- 每次正式发布必须同步更新 `CHANGELOG.md`，并确保标签、程序版本和 EXE 属性完全一致。

## 组件与职责

### 统一版本源

新增 `app/version.py`，供 Qt 应用、构建工具、测试和发布脚本共同读取。运行时不得依赖 Git 标签，因此源码包和打包后的程序都能稳定获取版本号。

### Qt 应用

`main.py` 将版本号写入 `QApplication`，主窗口标题或固定的界面信息区域显示 `v1.0.0`。版本展示不参与主题切换，也不引入新的网络请求。

### Windows EXE 元数据

新增版本资源生成工具，根据 `app/version.py` 生成 PyInstaller 使用的 Windows 版本资源。单文件版和目录版共用同一资源，包含以下信息：

- 产品名：`CommMonit`
- 文件描述：`串口旁路监控软件`
- 产品版本和文件版本：`1.0.0.0`
- 原始文件名：`CommMonit.exe`

两个 PyInstaller spec 文件都引用生成的版本资源。构建脚本必须先生成资源，再运行测试和打包。

### 更新日志

新增 `CHANGELOG.md`，按版本倒序记录新增、变更和修复内容。首个条目为 `1.0.0`，概括现有串口旁路监控、多进程监控、亮暗主题、软件多开和双形态 EXE 构建能力。

### 发布脚本

新增 PowerShell 发布脚本，接受目标版本并执行以下流程：

1. 校验工作区干净、版本格式正确且对应标签不存在。
2. 校验 `app/version.py`、`CHANGELOG.md` 和目标版本一致。
3. 运行测试并构建单文件版和目录版。
4. 创建带说明的 Git 标签，例如 `v1.0.0`。
5. 将分支和标签同步到 GitHub `origin` 与 Gitee `gitee`。

脚本在任何校验、测试、构建或推送步骤失败时立即停止，并明确显示失败步骤，不创建不完整的新标签。

## Gitee 仓库

- 所属账号：`yycz`（陈臻）
- 可见性：私有
- 页面显示名称：`串口旁路监控软件`
- 仓库路径：`commmonit`
- Git 远程名：`gitee`
- 默认分支：`main`

现有 GitHub 私有仓库继续使用 `origin`。Gitee 作为第二远程，不替换 GitHub 地址。首次发布时创建 Gitee 仓库、配置远程、推送 `main` 和 `v1.0.0` 标签。

## 数据流

`app/version.py` 提供版本号，Qt 应用在启动时读取并展示；构建工具读取同一版本号生成 Windows 版本资源；PyInstaller 将资源写入两种 EXE；发布脚本校验版本号和更新日志后构建、打标签并推送两个远程。整个流程不存在重复手工维护的第二版本号。

## 测试与验收

- 单元测试验证版本号符合语义化格式，并验证 Windows 版本元组转换正确。
- 运行现有全部测试，确保监控和主题功能无回归。
- 完成两种 PyInstaller 构建，确认两个 EXE 均存在。
- 读取 EXE Windows 版本信息，确认产品名、中文描述和 `1.0.0.0` 正确。
- 检查程序界面显示 `v1.0.0`。
- 检查本地、GitHub 与 Gitee 的 `main` 提交一致，两个远程都存在 `v1.0.0` 标签。
- 对本次修改的文本文件执行 UTF-8 无 BOM、CRLF 行尾和中文乱码扫描。

## 非目标

- 本次不增加自动更新、在线版本检查或安装程序。
- 本次不把 EXE 二进制直接提交进 Git 仓库。
- 本次不改变串口监控逻辑、界面布局或主题配色。
